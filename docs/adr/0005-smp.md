# ADR 0005: Multiprocessor (SMP) model

Status: proposed

## Context

The kernel currently runs on one CPU. With several CPUs, every piece of
shared kernel state can be accessed concurrently, and races in capability
operations or TLB management become privilege-escalation bugs, not just
crashes. Deciding the concurrency model before more subsystems exist is far
cheaper than retrofitting it.

## Decision

### Phase 1: big kernel lock

- One kernel lock (a fair ticket spinlock), taken on every kernel entry
  (syscall, interrupt, exception) and released on exit. The kernel is not
  preemptible while holding it.
- Rationale: microkernel operations are short, so contention stays low. seL4
  uses the same approach on multicore for the same reason, and it makes
  every subsystem correct by construction. Finer-grained locking is
  introduced only where measurements justify it, one subsystem at a time,
  each with its lock rules written down.
- Long operations, such as revoking a large subtree, are already
  preemptible and restartable (ADR 0003). They release the lock at
  preemption points so other CPUs make progress.

### Per-CPU state

- Each CPU has its own:
  - GDT, TSS and IST stacks, each stack with a guard page (as for CPU 0
    today)
  - kernel stack and idle thread
  - scheduler run queue
  - DRBG instance (ADR 0004)
- Per-CPU data is reached through the GS base: `swapgs` on entry from user
  mode, with the user GS base never trusted in kernel mode.
- All mutable kernel globals must be either per-CPU or protected by a
  documented lock. Code review rejects new globals that are neither.

### TLB shootdown

Invariant **S1**: no physical frame is reused while any CPU may still
cache a translation to it.

- Each address space tracks which CPUs have run it since its last flush.
- `unmap` sends a shootdown IPI to those CPUs and **waits for every
  acknowledgement** before the frame is released back to its Untyped.
- A CPU spinning for the kernel lock still services shootdown requests (it
  polls a per-CPU shootdown queue while spinning), so a shootdown issued
  under the lock cannot deadlock.
- PCID is used to avoid full flushes on context switch; a PCID is never
  reused for a new address space until it has been flushed everywhere.

### Memory ordering

- Shared variables use C11-style atomics (`__atomic_*` builtins) with an
  explicit memory order at every use.
- `volatile` is used only for MMIO and hardware-shared memory, never for
  synchronisation between CPUs.

### Interrupts

- The local APIC (x2APIC mode when available) replaces the legacy PIC,
  which will be masked.
- The I/O APIC (later MSI/MSI-X) routes device interrupts. Interrupt
  routing is controlled by `IrqHandler` capabilities, never by drivers
  directly.

### Speculative execution

- On address-space switch: IBPB where the CPU supports it, or when the
  incoming task is untrusted.
- Kernel page-table isolation (KPTI) on CPUs affected by Meltdown.

## Tests

- QEMU CI runs with `-smp 4` as well as `-smp 1`.
- Stress tests: concurrent `derive`, `revoke` and `delete` on shared
  cspaces; concurrent `map`, `unmap` and frame reuse while other CPUs
  access the same address space. S1 must hold throughout.
- A lock-order checker in debug builds once more than one lock exists.
- Later: a KCSAN-style data race detector.

## Consequences

- Throughput on many-core systems is limited by the big lock until finer
  locking is added. That is an accepted trade of performance for
  correctness at this stage.
- Every new subsystem's ADR must state its concurrency rules.
